# TAO 前端布局改版设计

## 目标

在不改变现有账号管理、批量任务、一条龙、代理、验证码、2FA 与导出能力的前提下，重构前端空间组织，降低批量操作的认知负担，并让上千账号场景下的筛选、任务跟踪与失败分类更顺手。

## 已确认的方向

- 采用 **A：工作台分区**。
- 默认进入 **账号清单**。
- 批量操作按模块分组，默认收起。
- 账号表格默认使用紧凑密度。
- 视觉风格采用 **深蓝导航 + 明亮工作区**。

## 信息架构

### 应用外壳

```
顶部栏：品牌 / 运行状态 / 全局搜索 / 设置
左侧导航：账号清单 / 任务中心 / 工具箱 / 代理与节点 / 导入与导出 / 日志 / 设置
主工作区：当前模块内容
```

左侧导航默认展开，折叠后保留图标栏；展开状态和当前模块使用本地偏好持久化。移动端将导航变为抽屉，不影响账号表格的横向滚动。

### 账号清单

账号清单是默认首页，保留现有数据和接口。页面由以下层级组成：

1. 页面标题与数量统计。
2. 状态统计卡和快速筛选。
3. 搜索、标签、代理、失败原因筛选。
4. 分组批量操作栏。
5. 紧凑账号表格。

点击行详情按钮打开右侧详情抽屉，展示会话、代理、验证码、2FA、失败原因和操作历史；不离开当前列表，也不清空当前选择。

## 批量操作分组

- **登录与验证码**：自动登录、重新登录、发送验证码、读取官方验证码。
- **代理与节点**：体检、代理审计、批量替换、节点分配。
- **导入与导出**：批量导入、一条龙、导出 session、号包、tdata、接码链接。
- **账号工具**：改 2FA、设备清理、标签、锁定/解锁、删除与恢复。

默认显示每组的常用动作，其余动作由分组展开；选中账号后显示上下文栏，并明确显示“已选 N 个”。不相关动作置灰并给出简短原因。

## 任务与长操作

一条龙、自动登录、改 2FA、导出和体检继续使用服务端任务接口。长任务以右下角任务卡显示：阶段、进度、成功/失败计数、检查点、暂停/继续、查看详情和导出结果。任务卡不覆盖主表格，也不阻塞互不相关的模块。

任务中心集中展示所有任务，失败条目按阶段和错误分类，可从任务结果跳转到账号筛选结果。

## 视觉与交互规则

- 左侧导航使用深蓝背景，当前项使用蓝色高亮和指示线。
- 工作区使用明亮背景、白色卡片和低对比边框。
- 成功、处理中、待核对、失败、锁定使用统一语义色和徽章。
- 表头固定；列宽可拖动；紧凑行高优先保证批量场景的信息密度。
- 所有高风险或批量动作使用统一确认弹窗；长任务使用非阻塞任务卡。
- 自动刷新只更新数据，不覆盖用户未提交的输入、筛选和文件选择。

## 响应式规则

- 宽屏：导航栏 + 主工作区 + 右侧详情抽屉。
- 中等宽度：导航可折叠，批量栏保留在表格上方。
- 小屏：导航进入抽屉，批量栏变为底部浮层，表格水平滚动，详情抽屉改为全屏面板。

## 兼容与迁移

- 保留现有 `data-widget`、账号表格节点、任务 API 和工具函数入口，先改布局容器，再迁移视觉层。
- 不修改账号数据结构、任务持久化格式和导出格式。
- 旧的自定义布局偏好无法映射的部件回退到默认工作台顺序，并提供一次性“恢复默认布局”入口。
- 迁移期间保留旧按钮语义和快捷操作，避免已有操作习惯失效。

## 验收标准

1. 首屏默认进入账号清单，批量工具不再挤满顶部。
2. 账号、任务、工具、设置可通过左侧导航一跳到达。
3. 任务运行时主表格仍可筛选、查看详情和处理其他模块。
4. 1000+ 账号列表滚动和筛选保持可用，自动刷新不覆盖草稿。
5. 桌面、小屏两种宽度下无横向页面溢出；表格仅自身滚动。
6. 现有前端构建、Node 检查、Python 测试和 Web 端回归测试全部通过。
